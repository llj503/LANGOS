# 真机启动链路与平台映射（实测记录）

> 这份文档里的每一条都是**从真镜像里挖出来的**，不是推测。
> 提取方式：只读挂载 p2 → 读 `/etc/emulationstation/es_systems.cfg`、
> `/usr/local/bin/*`、`/home/ark/.config/retroarch*/cores/`。
> 复现脚本：`build/probe-ra.sh`、`build/probe-ra2.sh`、`build/probe-sudo.sh`、
> `build/dump-systems.py`、`tests/real-launch-dryrun.py`。

镜像：`ArkOS4Clone-09052026-vagaretro.img`（9.9 GB，Ubuntu 19.10 eoan arm64，RK3326）

## 1. 从 ES 到游戏的完整链路

```
systemd: emulationstation.service  (User=ark, Type=simple, Restart=on-failure)
   └─ /usr/bin/emulationstation/emulationstation.sh
        └─ emulationstation 二进制  ← 我们的钩子就插在这里
             └─ 读 /etc/emulationstation/es_systems.cfg 的 <command> 模板
                  └─ 把 %ROM% %EMULATOR% %CORE% %GOVERNOR% 替换掉
                       └─ system() 执行
                            └─ sudo perfmax performance <rom>   ← 调频
                            └─ nice -n -19 /usr/local/bin/<EMULATOR> -L .../cores/<CORE>_libretro.so <rom>
                            └─ sudo perfnorm                     ← 恢复
```

**关键点：`/usr/local/bin/retroarch` 不是二进制，是个 bash 包装脚本**
（3201 字节）。它做三件事：把 `/dev/tty0` 放开并清屏、跑 `buttonmon.sh` 处理
手柄热键与 netplay，最后才 `exec /opt/retroarch/bin/retroarch -c
/home/ark/.config/retroarch/retroarch.cfg "$@"`。

所以我们的启动器**照抄 es_systems.cfg 的 `<command>` 模板**就是最正统的做法 ——
等于完全复用 ArkOS 自己的启动路径（调频、tty 交接、手柄监听、netplay 全都在），
不需要另起一套。这正是"RA 换成调用 Linux 的"最省事的实现。

## 2. 占位符语义（都会在真机上被 ES 展开）

| 占位符 | 含义 | 我们的处理 |
|---|---|---|
| `%ROM%` | ROM 路径 | `shlex.quote()` 后填入 |
| `%EMULATOR%` | 模拟器名 | 取该 system 第一个 `<emulator name=…>` |
| `%CORE%` | 选中的 core | 见第 4 节 |
| `%GOVERNOR%` | **调速器名**，不是路径 | 固定填 `performance` |

`%GOVERNOR%` 的真相在 `perfmax` 脚本里：

```bash
if [[ "$1" == "kodi" ]]; then ... elif [[ "$1" == "powersave" ]]; then ...
elif [[ "$1" != "ondemand" ]]; then
    echo "$1" > /sys/devices/platform/${gpu}.gpu/devfreq/${gpu}.gpu/governor
```

也就是说 `sudo perfmax %GOVERNOR% %ROM%` 实际是 `sudo perfmax performance <rom>`，
`$1` 直接当 governor 名写进 sysfs。填 `performance` 是对的。

## 3. 三个必须知道的坑

### 3.1 `es_systems.cfg` 不是合法 XML

第 2761 行：

```xml
<command>sudo chmod 666 /dev/tty1; %ROM% 2>&1 > /dev/tty1; printf "\033c" >> /dev/tty1</command>
```

`2>&1` 里的 `&` **没有转义**。`xml.etree.ElementTree` 直接抛
`ParseError: not well-formed (invalid token)`。ES 自己吃得下，我们必须跟着容错：

```python
_BARE_AMP = re.compile(r"&(?!(?:[a-zA-Z][a-zA-Z0-9]*|#[0-9]+|#[xX][0-9a-fA-F]+);)")
def sanitize_xml(text): return _BARE_AMP.sub("&amp;", text)
```

先按原文解析，失败再容错重试。**这个 bug 只在真机上暴露** —— 自测用的
合成 cfg 是合法的，所以单测夹具里特意也留了一个裸 `&`，防止再漏。

### 3.2 `psp` 和 `dos` 这两个系统名不存在

真机 133 个系统里的正确名字是：

| 前端 platform.id | ArkOS 系统名 | 真实目录 |
|---|---|---|
| PSP | **`ppsspp`**（不是 psp） | `/roms/psp/` |
| DOS | **`msdos`**（不是 dos） | `/roms/dos/` |
| NGPC | `ngpc` | `/roms/ngpc/` |

### 3.3 `snes` 重名

`snes` 在 cfg 里出现两次（`/roms/sufami/` 和 `/roms/snes/`），后者才是正经目录。
解析时按"目录是否真实存在"择优，而不是无脑取后一条。

## 4. core 的选择

不能无脑取 cores 列表的第一个 —— 真机上有列了但没装的，
**更有列了、装了、却一跑就挂的**（见下面 GBA 那条）：

- 每个系统的 `<cores>` 顺序以 `<core default="true">` 优先。
- 必须逐个检查 `${core}_libretro.so` 是否真在 cores 目录里，取第一个存在的。
- 光"文件存在"还不够，见 `vagaretro-shell.py` 里的 `BAD_CORES` / `FORCE_CORE`：
  `gpsp_ezode_mod` 文件在、架构也对，但对**所有**输入都报
  `Failed to materialize ROM from memory`，必须整体跳过。
- **例外**：standalone 那几家（`nds`/`saturn`/`dreamcast`/`naomi`/`ppsspp`）
  的 `%CORE%` 不是 `.so`，而是给自家 `.sh` 看的代号，**不能**做文件校验。

### 两个必须"还原成真实路径"的平台

前端只认兼容软链树 `<compat_dir>/<ID>/<file>`，但下面这几个 ArkOS 包装脚本
**会从 ROM 路径里抠目录名**，拿到 `/home/ark/.vagaretro-roms/...` 就抠错了：

- **SS**：`saturn.sh` 里 `directory=$(dirname "$2" | cut -d "/" -f2)`。
  原厂 `/roms2/roms/SS/x.chd` → 第 2 段 `roms2`（对）；
  兼容路径 → 第 2 段 `home`（错），于是去建/找一个不存在的备份目录，直接启动失败。
- **EASYRPG**：卡二上的游戏本体是**同名目录** `FF72DR/`，旁边的 `FF72DR.zip`
  只是个旁挂包（`FF72DR.zip.save/` 这个 ES 存档目录名可以证明 ES 认的是那个 .zip）。
  直接把 .zip 喂给核心起不来，要先换成同名目录。

处理方式见 `build_launch_script()`：对 `STANDALONE_SYSTEMS` 调
`os.path.realpath()` 还原真实路径；EASYRPG 额外先做一次"同名目录优先"的条目修正。
`retroarch` 那套不看路径结构，不必绕这一圈。

**注意**：`/roms2` 是**只读**的（TF2 那张卡），所以 `/roms2/saturn/yabasanshiro`
存档目录建不出来，SS 游戏的存档写不进去。启动不受影响。

**PS1 走的是 32 位那套**：`/usr/local/bin/retroarch32` +
`/home/ark/.config/retroarch32/cores/`（319 个 core，另一套目录）。
命令模板里写了两次 `%EMULATOR%`，替换后目录自动就对上了 —— 不用特判，
但 config.ini 里的 `ra_cores` 兜底路径要跟着换。

两个 cores 目录：`retroarch/cores` 424 个、`retroarch32/cores` 319 个。

## 5. 为什么 weston 必须以 root 跑

`emulationstation.service` 是 `User=ark`、`Type=simple`、**没有分配 tty**。
weston 的 DRM 后端在非 root 下要靠 logind 的 seat 授权，而 systemd 服务不是
tty 会话、没有 seat —— 所以会失败。

查过 `/etc/sudoers`：

```
ark	ALL=NOPASSWD: ALL
```

所以启动器里直接 `sudo -n weston …` 即可。**连带两个后果必须一起处理**：

1. **宿主也得跟着以 root 跑**（否则连不上 root 创建的 Wayland socket），
   于是它写出的东西都成了 root 的。
2. **启动请求文件不能放 `/tmp`** —— `/tmp` 带 sticky 位，`ark` 删不掉 root 建的
   文件，启动器又跑在 ark 下，结果是**同一个游戏被无限重复启动**。
   现在请求文件固定在 `/opt/vagaretro/launch.sh`（该目录属主是 ark）。

停 weston 也有讲究：`$!` 拿到的是 `sudo` 的 PID 不是 weston 的，所以按
命令行特征收尾：`sudo -n pkill -f "weston .*--socket=wayland-vagaretro"`。

| 指标 | 之前 | 现在 |
|---|---|---|

| 前端平台数 | 20 | **31** |

### 新增的 11 个平台

`N64` `GW`(Game & Watch) `MS`(Master System) `ARCADE`(卡二目录是 `fbneo`) `OPENBOR`
`ATARI2600` `ATARI7800` `LYNX`(Atari Lynx) `PICO8` `PORTS`(移植游戏) `EASYRPG`(RPG Maker)

每个都要同时改**三处**，少一处就表现为"平台在但没游戏"或"点下去没反应"：
1. 前端 `index.html` 的 `platforms` 数组（id 就是卡二目录名）
2. 宿主 `PLATFORM_MAP`（id → es_systems.cfg 系统名）
3. 宿主 `PLATFORM_CORE`（兜底 core 名；standalone 的填空串）

另外 `PLATFORM_CORE`/`STANDALONE_SYSTEMS` 要认得这批走**自家 .sh 包装脚本**的系统：
`n64.sh` / `OpenBor.sh` / `easyrpg.sh` / `pico8.sh` / `AltSDL.sh` ——
它们的 `%CORE%` 只是个代号，**不能**拿去 cores 目录里校验 `.so` 存在。

### 三个"只有真卡才会暴露"的坑

1. **这块卡 `mount` 显示 `type vfat`，但实际区分大小写。**
   `/roms2/roms/OPENBOR` 直接 ENOENT，`openbor` 才在。前端 id 是全大写的，
   照字面拼就会落到悬空链接上、界面显示 0 个游戏（NAOMI 白丢 43 个 ROM 且无报错）。
   修法不是逐条写死映射，而是加一个带回退的 `_resolve_child()`。
   顺手收益：卡二 `WS/` 下还分了 `WS/` 与 `WSC/` 两个子库，
   映射成 `WS -> WS/WS`(90) + `WSC -> WS/WSC`(82)，白捡一个能用的 WSC。
2. **ROM 是递归存的。** FC 3763 / GBA 1534 / MD 765 / SFC 702 / WS 172 / GB 66
   全在分类子目录里（`01-动作游戏/…`），平台根目录下只有个 xml。
   原来"只扫一层"的写法让这几个平台显示 0 个游戏。
   现在递归 3 层，跳过 `images/image/media/videos/boxart` 与 `.` 开头的目录。
   **例外**：`PORTS`（每个端口一个游戏数据目录）和 `EASYRPG` 绝对不能递归，
   用 `NO_SUBDIR_SCAN` 挡掉 —— 它们的真入口是平台根目录下的 `.sh`。
   嵌套 ROM 要分开发"路径"和"显示名"（`{name, title}`），否则卡片上带一串目录前缀。
3. **扩展名白名单在宿主和前端各有一份**（`ROM_EXTS` 与 `exts`）。
   宿主预扫描过一遍、前端 `listDir` 再过一遍，**少改一边就是空列表**。
   按卡二实际内容补了 `a26 a78 lnx sms n64 z64 v64 cso cdi img p8 pak sh easyrpg m3u`；
   特意**不收 `png`** —— PICO-8 的封面跟卡带在同一层，收进来会混进游戏列表。

### 前端分片渲染

卡二上 FC 一个平台就 3763 个 ROM，一次性 `innerHTML` 塞几千张卡在这台机器上会卡住好几秒。
实测把"开一个平台"拆开计时，**大头完全不在数据通道**：

| 环节 | 耗时（60 张卡） |
|---|---|
| 宿主 `listDir` 造 JSON（3763 条） | 85ms |
| 前端 `JSON.parse` | 37ms |
| `Array.map` 成游戏对象 | 23ms |
| `innerHTML` + 强制布局 | **6ms + 约 500ms** |

所以：首屏只插 60 张，尾部放哨兵 + `IntersectionObserver` 按需追加
（实测 DOM 元素总数被压在 **714 个**，不分片是几万）；
手柄导航走到已渲染末尾时先续一片再算下标；封面只处理刚追加的那片
（原来每次对整页 `querySelectorAll`，越滚越是 O(n²)）；
`.game-card` 加 `contain: layout style`，`transition: all` 收窄成具体属性
（**不能**加 `contain: paint`，会裁掉选中态的外发光）。

### 真机性能探针的两条纪律

- 结果**不要走 `console.log`**（宿主虽然注册了转发 hook，实测不出东西），
  用 `AndroidBridge.executeShellCommand` echo 到文件。
- 命令通道是**覆盖式**的：宿主把命令写进 `<APPDIR>/launch.sh`，
  外层启动器轮询到这个可执行文件才 bash 它，连发多条会互相冲掉。
  → 探针全程只攒字符串，**最后一次性发一条**。

### 已知问题：卡二被降成只读

`dmesg` 里持续刷 `FAT-fs (mmcblk1p1): error, fat_get_cluster: invalid cluster chain (i_pos 0)`，
挂载参数带 `errors=remount-ro`，所以 `/roms2` 现在是 **ro**，`touch` 报
`Read-only file system`。卡也用满了（116G/117G，99%）。

- 读 ROM、启动游戏都不受影响；
- 但**存档写不进去** —— NAOMI 的 `.nvmem/.eeprom`、DC/SS 的存档就存在 ROM 旁边。
- 这是卡上的数据问题，不是前端问题。建议先整卡备份，再 `chkdsk /f`（Windows）
  或 `fsck.vfat`，并腾出空间。

## 一、端到端启动：真机实测通过

用探针让前端自己发起一次启动（走的正是用户按下 A 的真实代码路径）：

## 二、bug 1：`%CORE%` 不该跨 emulator 合并（DC/SS/NAOMI 全挂）

### 现象
`dreamcast.sh` / `saturn.sh` / `naomi.sh` 这三个包装脚本把 **`$2` 当 ROM 用**：

```bash
# dreamcast.sh / naomi.sh
$FLYCAST_BIN "$2"
# saturn.sh
$YABA_BIN -r 3 -i "$2"
# 而且用 $2 的第 2 段当"媒体根"
directory=$(dirname "$2" | cut -d "/" -f2)
```

它们的命令模板却是 `<脚本> %EMULATOR% %CORE% %ROM%`，也就是 `$2` 本该是 **core**。

### 根因
EmulationStation 的语义是：**`%CORE%` 只取"当前被选中的那个 emulator"的 core**；
选中的是 `standalone-*` 时它压根没有 `<cores>`，`%CORE%` 替换成**空字符串**，
于是 `$2` 自然落回 ROM。

但 `parse_es_systems()` 把**所有 emulator 的 `<cores>` 合并成了一张表**：

```
dreamcast 的 emulators 顺序：
  standalone-r7(无 cores)  standalone-2022  standalone
  retroarch32(flycast32_rumble, flycast_xtreme, reicast_xtreme)  ...
```

合并后 `cores[0]` 变成 `flycast32_rumble`，命令就成了

```
dreamcast.sh standalone-r7 flycast32_rumble '…/VR战士3.chd'
                            ^^^^^^^^^^^^^^^^ 多占了一个参数位
```

flycast 会去加载一个叫 `flycast32_rumble` 的"游戏文件" —— 必然起不来。

### 修法
`core` 只收**被选中 emulator 自己**的 `<cores>`；全量并集另存 `cores_all`，
只在"命令确实要 `-L` 加载某个 .so"（retroarch 系）且选中的 core 一个都没装时兜底。
`pick_core()` 在解析不到 cores 目录（standalone）时返回 `cands[0] or ""`。

改动前后 diff —— **只有 3 行**，其余 26 个平台一字未动：

```
- dreamcast.sh standalone-r7 flycast32_rumble '…/VR战士3.chd'
+ dreamcast.sh standalone-r7  '…/VR战士3.chd'
- naomi.sh standalone-r7 flycast …/18wheelr.zip
+ naomi.sh standalone-r7  …/18wheelr.zip
- saturn.sh standalone-nobios yabasanshiro '…/D_CD1.chd'
+ saturn.sh standalone-nobios  '…/D_CD1.chd'
```

**n64 不受影响**（它必须拿到 core）：`n64.sh` 的首个 emulator 是 `retroarch32`，
**有** `<cores>parallel_n64`，所以仍然是 `n64.sh retroarch32 parallel_n64 <rom>` ✅。

### 怎么自己验
`build/table-core.py`（真机跑）会把"命令要不要 %CORE%"和"选中 emulator 的 cores"
并排列出来 —— 一眼就能看出哪些系统是"要 %CORE% 但 cores 为空"的雷。

## 三、bug 2：`/$directory/xxx` 落在 /home 下，资源全找不到

### 现象
上面那几个脚本用 **ROM 路径的第 2 段**当"媒体根"：

```bash
directory=$(dirname "$2" | cut -d "/" -f2)     # /home/ark/.vagaretro-roms/DC/x -> "home"
[ -d "/$directory/bios/dc" ] || mkdir -p "/$directory/bios/dc"
```

我们的兼容目录在 `/home/ark/.vagaretro-roms/`，第 2 段永远是 `home`，
于是它去找 `/home/bios/dc` —— 而真正的 BIOS 在卡二：

| 脚本 | 找的路径 | 真身 | 传兼容目录的后果 |
|---|---|---|---|
| dreamcast/naomi | `/home/bios/dc` | `/roms2/bios/dc`（19 项，含 dc_boot.bin） | **没 BIOS，起不来** |
| saturn | `/home/bios/saturn_bios.bin` | `/roms2/bios/saturn_bios.bin` | -nobios 分支用不到，但同样错 |
| pico8 | `/home/pico-8/pico8_64` | `/roms/pico-8/`（且**可执行文件压根没装**） | 找不到启动器 |
| ppsspp | `/home/psp/ppsspp` | `/roms/psp/ppsspp` | 丢弃用户已有配置 |

### 为什么不能简单地"改传真实路径"
试过 `realpath`：dreamcast 要 `roms2`（BIOS 在卡二），pico8 要 `roms`
（pico8_64 在卡一）—— **两张卡分头持有资源，选哪边都有一半是坏的**。
而且 `/roms` 和 `/roms2` 都是 exFAT/vfat，**根本建不了软链**，
所以也没法在卡上做兼容层。

### 修法：`/home` 下做「叠加目录」
`bridge_media_dirs()` 自动从**我们服务的系统**引用的 .sh 里抽出
`/$directory/<名>` 用到的名字，然后在 `/home/<名>` 建一个**真目录 + 逐项软链**：

```
/home/bios      <- /roms2/bios + /roms/bios   (388 项软链)
/home/pico-8    <- /roms/pico-8               (7 项)
/home/psp       <- /roms/psp                  (1 项)
/home/easyrpg   <- /roms/easyrpg              (3 项)
```

* **读**：命中两卡上的真文件（`/home/bios/dc/dc_boot.bin` ✅）；
* **写**：落在 `/home`（可写）—— 正好绕开"卡二只读"；
* `dreamcast / saturn / naomi / atomiswave` **故意不建**，留给脚本自己
  在可写的 `/home` 下 `mkdir`（比如 `saturn.sh` 要建 `saturn/yabasanshiro`）。

两级收窄，避免在 `/home` 里乱建目录：只扫 es_systems.cfg 的 command →
再只认 `PLATFORM_MAP` 映射出来的那批系统（否则 atari800/coco3/wolf 这些
无关系统也会被桥一遍）。

## 四、最终核对

```
29 个平台：DOS / NGPC 为空（两卡上真没有这两个机种的 ROM，
                        /roms/msdos 不存在、/roms/ngpc 与 /roms/dos 都是空目录）
11001 个游戏条目 / 31 个目录 / 24 个元数据文件
19 个 retroarch core 全部在位；10 个包装脚本全部可执行
perfmax / perfnorm 在位；pico8hotkey.service 在位
GPU: EGL 1.4 Bifrost-"r13p0-01rel0" / GL renderer: Mali-G31 / Output 'DSI-1' enabled
     首启一次成功，**0 次软件渲染兜底**
空闲占用：python3 / WebKit / weston 均不在活跃榜（0%），
     剩余 5~6% 是内核线程（WiFi RTW_CMD_THREAD、kworker 卡 D 状态等 I/O、
     Rockchip 电源管理），与前端无关
```

## 五、仍然遗留

1. **卡二被内核重挂成只读** —— `dmesg` 报 `FAT-fs (mmcblk1p1): error,
   fat_get_cluster: invalid cluster chain`，卡满到 99%（116G/117G），
   内核按 `errors=remount-ro` 挂成了 ro。影响：DC/NAOMI/SS/PSP 的**存档写不进**。
   前端无法解决，建议整卡备份后 `chkdsk /f`（Windows）或 `fsck.vfat`。
   注意：叠加目录方案让 DC/NAOMI 的 BIOS 能读到，但 flycast 若往
   `/roms2/bios/dc/` 写 NVRAM 仍会失败。
2. **PICO-8 没有运行时** —— `/roms/pico-8/pico8_64` 全盘不存在（PICO-8 是
   商业软件）。93 个 .p8 卡带在，但 ES 自己也会因同样原因起不来。
   把 `pico8_64`（或 `pico8_dyn`）放进 `/roms/pico-8/` 即可。
3. **DOS / NGPC 无 ROM** —— 两卡上都没有这两个机种的内容。
4. 宿主（GTK/WebKit）仍走 wl_shm，未上 GPU（r13p0 blob 缺 wayland-egl）。

# 第三轮：START 设置页复刻 ArkOS 原生 ES —— 2026-09-14 晚

## 一、设计原则：不自己发明存储

用户要求 START 设置"复刻 ArkOS 原生设置接口"。关键决定：**不做一套自己的
配置文件**，每一项都写到这台机器原生 ES 本来就会读/写的**同一个地方**。
这样在网页里改完设置、退出前端回到 ES，设置照样生效，两款前端不会各说各话。

各项的真实落脚点（逐条在真机上验过）：

| 设置项 | 落脚点 | 写入方式 |
|---|---|---|
| 音量 | `Playback` 混音器 + `/var/lib/alsa/asound.state` | `amixer sset Playback N% && alsactl store` |
| 亮度 | `/sys/class/backlight/backlight/brightness` | `brightnessctl set N%` |
| CPU 调速器 | `/sys/devices/system/cpu/cpufreq/policy0/scaling_governor` | `echo X \| tee` |
| GPU 调速器 | `/sys/devices/platform/ff400000.gpu/devfreq/ff400000.gpu/governor` | `echo X \| tee` |
| DMC(内存)调速器 | `/sys/devices/platform/dmc/devfreq/dmc/governor` | `echo X \| tee` |
| ES 的 13 个选项 | `/home/ark/.emulationstation/es_settings.cfg` | 正则原地替换那一行 |

菜单树、条目名照抄原生 ES（名字是从 `/usr/bin/emulationstation` 里
`strings` 抠出来的）：PERFORMANCE / SOUND / UI / SCREENSAVER / ADVANCED /
SYSTEM INFO / QUIT，共 7 个主菜单、18 个可调项。

## 二、两个真 bug（都是"静默失效"型）

### bug 1：`subprocess` 从未 import —— **所有写操作全部失效**

`_sh()` 里用了 `subprocess.Popen`，但文件顶部的 import 列表里**没有
`subprocess`**。因为 `_sh()` 的异常被 `except Exception: return 1, str(e)`
吃掉了，表现是：

- 音量永远读到 `-1`（前端显示"不可用"）
- 所有 `setSetting` 都会返回失败，但**日志里只有一行 `name 'subprocess'
  is not defined`**，很容易当成"设备不支持"

排查过程走了弯路：一开始怀疑是竞态（codec 异步探测）、PATH、HOME、登录
shell，把 env 各种组合都试了一遍全成功。最后是**在服务进程内部** import
宿主模块直接调 `_sh()`，才打出这句真话。

教训：**用 `except Exception` 包住的工具函数，一定要把异常内容记进日志**，
否则它会把"代码写错了"伪装成"环境不支持"。

### bug 2：前端没有设置值缓存 —— 改了不显示

`settingsData()` 每次调用都去 `AndroidBridge.getSettings()` 重新 parse 一遍。
`renderSettings()` 里每行都要取值，一页 7 行就是 7 次全量序列化+解析；
更要命的是**界面显示的永远从桥接取**，桥接那侧没同步就显示旧值。

headless 校验直接抓到了这个："桥接调用: set cpu_governor=powersave" 但
"改后显示: performance"。

修法：页面侧加一份 `settingsCache`，首次从桥接灌一次，之后读写都走缓存，
`writeSetting()` 写完立即回写缓存；进设置页时 `invalidateSettings()`
丢掉重灌（保证看到的是别处改过的最新值）。

## 三、三层验证（本机 + 真机）

设置这种东西"看起来生效了"特别容易自欺，所以搭了三层：

1. **本机静态检查** `build/check-front.js`
   语法 + 死代码残留 + 真机不支持的特性（aspect-ratio / content-visibility /
   `loading="lazy"`）。注意要**先剥注释再扫**，否则满篇"不支持 X 所以…"
   的解释性注释会把结果淹掉。

2. **本机 headless 交互验证** `build/check-settings-dom.js`
   把 `AndroidBridge` 换成假的（值用真机上抓到的真值），用 CDP 驱动
   Edge/Chrome 真跑一遍：进设置页 → 数出 7 个主菜单 → 进子菜单看值 →
   按 → 改值 → 按 B 返回看光标落点 → 切布尔 → 查只读项 → 危险动作要
   二次确认。**10/10 通过**。
   没有真机探针也能验，是因为真机上想读 DOM 得改宿主代码开探针，成本高。

3. **真机逐条落盘验证** `build/apply-settings-test.py`
   每条都是"改前读 → 改 → 改后读 → 必须真变 → **恢复原值**"。
   `es_settings.cfg` 那几条还额外验了：
   - **只改一行**（行数 22→22，diff 只有第 2 行）—— 证明是原地改不是重写
   - 类型标签正确（DrawClock 是 `<bool>`，MaxVRAM 是 `<int>`）
   - 非法值被拒（"不是数字"、"abc"、"bogus_gov"、未知 key 全部返回失败）
   
   **30/30 通过**，且跑完设备状态与跑前一致。

## 四、一个坑：amixer 的百分比是"非线性取整"

测试里"音量恢复原值 5%"曾经 FAIL，读到 4%。查下来是 ALSA 自己的行为：
百分比到原始 0–255 是非线性映射，raw 12 和 raw 13 读出来都是 4%。
来回 set/get 会漂 1 个百分点，**不是我们的 bug**。测试容差改成 ±1。

（也确认了这是 amixer 的显示问题：`amixer sset Playback 13` 之后
`sget` 显示 4%。）

## 五、部署脚本的坑

`tools/deploy-device.sh` 只推 `config.ini` / `vagaretro-front.sh` /
`vagaretro-shell.py` 三个文件，**不推 `index.html`**。这次改的主要就是
`index.html`，如果用老脚本会出现"部署了但界面没变"的假成功。
所以另写了 `build/deploy-settings.py`，两个文件都推，并且**用 MD5 对照**
确认落位的就是本地那份（真机上的 `index.html` 是 82 KB / shell 是 92 KB，
传输 + CRLF 转换都可能出问题，必须验）。

# 第四轮：禁用 ES 前端 + 一次黑屏事故复盘 —— 2026-09-14 晚

## 一、起因

连着三个现象，其实是**同一条因果链**：

1. 用户截图指出顶栏有个孤零零的小 "L"（见第五节，是另一码事）
2. "怎么还是 es 前端"
3. "设备现在黑屏"

## 二、"怎么还是 es 前端" —— 有 4 条路会掉进 ES

`vagaretro-front.sh` 里原来写了一个 `run_es()`，**4 个地方**会调它：

| # | 触发条件 | 后果 |
|---|---|---|
| ① | `config.ini` 里 `enabled=0` | exec 原版 ES |
| ② | `index.html` 缺失 | exec 原版 ES |
| ③ | native/cog/chromium 三种渲染路径全失败 | exec 原版 ES |
| ④ | **前端自己正常退出**（用户在设置里点"退出前端"） | exec 原版 ES |

第 ④ 条最阴 —— 代码长这样：

```bash
log "return to ES"
run_es "$@"          # ← FRONTEND_RC==0 也走这里
```

也就是说**"退出前端"的下一站就是 EmulationStation**。用户点一次退出，
看到的就是 ES，感觉像"改造压根没生效"。

更糟的是还有一条**永久锁死**逻辑：连续 3 次启动失败就自动
`sed -i 's/enabled=.*/enabled=0/' config.ini`，此后每次开机都是 ES，
不 ssh 进去改回来就再也见不到网页前端。

## 三、"黑屏" —— ES 抢 DRM 把 weston 的原子提交搞废了

这是本轮最值钱的一条。weston 日志：

```
[05:08:09.150] atomic: couldn't commit new state: Invalid argument
[05:08:09.150] applying repaint-start state failed: Invalid argument
```

现象极具迷惑性：

- `systemctl is-active emulationstation` → **active**
- weston / weston-shell / vagaretro-shell.py 进程**全都在**
- 服务日志也**没有**任何 error
- 但屏幕就是**全黑**，而且再也画不出来

根因：**RK3326 的 DRM 同一时刻只能有一个 master**。ES（或任何别的
DRM 客户端）在 weston 之外摸过一次 CRTC，weston 手里那套保存的原子
状态就失效了，之后每次 commit 都 `Invalid argument`。
weston 不会自己恢复，也**不会退出** —— 所以进程活着、屏幕死了。

> 恢复手段只有一个：`systemctl restart emulationstation`（重建 weston）。

排查时先怀疑"谁占着 DRM"：

```bash
fuser -v /dev/dri/card0          # 只有 weston 一个才算正常
for p in /proc/[0-9]*; do ls -l $p/fd 2>/dev/null | grep -q '/dev/dri/' && \
    echo "$p $(tr -d '\0' < $p/cmdline)"; done
```

顺带记一个**踩坑**：`/dev/fb0` 在 GL 合成器下是**假的**，
`dd if=/dev/fb0` 抓下来整片 0xFF，转成图是一张白纸。
**别指望它截图**。要真截图得让 weston 加载 `screenshooter` 插件
然后注入 MOD+S，成本高，当时放弃了。
（`build/fb2png.py` 是这次写的转换器，留着一以后有用，但前提是
得先能抓到真帧。）

## 四、处理：把 ES 彻底禁用

### 4.1 ES 二进制改名停用

```
/usr/bin/emulationstation/emulationstation
  -> emulationstation.disabled-es
```

**改名而不是删除**：一眼看得出被停用了，恢复就一句 `mv` 回去。
改之前先确认过没有别的脚本真的执行它：
全盘 grep 只命中 `vagaretro-front.sh`（默认参数）和
`Ghost Loader.sh`（只是 `pkill`/`pgrep` 匹配名字，无害）。

### 4.2 启动器去掉全部回退

`run_es()` 保留但加了闸门 —— 必须**同时**满足两个条件才会真的 exec ES：

```bash
touch /opt/vagaretro/allow-es                                  # 显式开闸
mv /usr/bin/emulationstation/emulationstation.disabled-es \
   /usr/bin/emulationstation/emulationstation                  # 二进制放回去
```

不满足就 `return 1`，调用方继续往下走。四个调用点改成：

- ① `enabled=0` → 在 tty1 打提示，`exit 0`（正常退出，systemd 不重启）
- ② 页面缺失 → 打提示 + `sleep 15` + `exit 1`（交给 systemd 重试）
- ③ 渲染全挂 → 同上
- ④ 正常退出 → 只留一句回执，**哪儿也不去**

同时**删掉了"连续失败 3 次自动写 enabled=0"**那段 —— 没有 ES 可回退了，
再自动停用前端只会得到一块死屏。

`sleep 15` 不是凑数：`emulationstation.service` 里没写 `RestartSec`，
systemd 默认只等 100ms，不 sleep 就是热循环刷日志。

### 4.3 `.es` / `.ra` 两个变体也必须打补丁（静默陷阱）

ArkOS 在同一个目录放了**三份**启动脚本：

| 文件 | 内层启动行 | 谁用它 |
|---|---|---|
| `emulationstation.sh` | `"$esdir/emulationstation" "$@"` | 开机默认 |
| `emulationstation.sh.es` | `"$esdir/emulationstation" "$@"` | 开机菜单 "1) Emulationstation" |
| `emulationstation.sh.ra` | `retroarch "$@"` | 开机菜单 "2) Retroarch" |

**它们之间会互相 `cp -f` 覆盖**（见各自的 case 分支）。所以只在 `.sh`
上打补丁是不够的：用户在开机时按住 East 键进 BaRT 菜单、选一次
"2) Retroarch"，`.ra` 就被复制成 `.sh`，**下次开机直接进 RetroArch，
网页前端再也回不来**。三份全打之后，这些互覆盖就都无害了。

`.ra` 里没有 `esdir` 变量，所以那边补的是绝对路径。

### 4.4 补丁方式：函数化 + 幂等 + 命中数校验

注入脚本里原来是一段 if/else 直接内联 sed。改成 `patch_one()` 函数，
对三个文件依次调用。每条都：

- 已经打过就跳过（幂等）
- **要求命中数恰好 = 1**，否则打印实际命中并 `die`（宁可不打，也别打半截）
- 打完立刻 `grep -q` 校验钩子在不在

改之前把设备上的 `.es`/`.ra` 拉到本地**试跑了一遍 sed**，
确认命中 1 处、`$esdir`/`$@` 没被误展开、`bash -n` 通过，才动的真机。

## 五、顺带：顶栏那个小 "L"

`index.html` 里：

```html
<div class="logo-icon">L</div>
<div class="logo-text">LANGOS</div>
```

`.logo` 是 `display:flex; gap:20px`，而 **`.logo-icon` 压根没有对应的 CSS 规则**
—— 于是那个裸文字 "L" 按浏览器默认样式渲染出来，还额外撑出 20px 空隙。
删掉那一行即可。

为了不再出同类问题，写了 `build/check-classes.js`：
扫出「HTML 里用了、`<style>` 里没定义」的 class（会裸渲染的元素）。
这次扫下来 A 段为空，说明只有这一个。

> 写这个检查器本身踩了两个坑，都记在脚本注释里：
> ① 正则**没有捕获组**时 `m[1]` 是 undefined，脚本段会静默变成空，
>    结果所有模板串里的 class 都被误报成"死 CSS"；
> ② 把「找 CSS 类」的正则套到**全文**上，JS 的 `.forEach`/`.map`/`.push`
>    会被当成类定义（一度报出"已定义 235 个 class"的离谱数字）。
>    必须**只**从 `<style>` 块里取。

## 六、验证

| 项 | 结果 |
|---|---|
| 启动器语法 `bash -n` / 部署 MD5 对照 | OK / 一致 |
| `.sh` `.es` `.ra` 三份钩子 | 各 1 处 |
| ES 二进制可执行 | **否**（已改名） |
| `run_es` 判据单跑 | 返回 1，不 exec |
